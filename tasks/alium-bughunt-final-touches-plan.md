## Bug hunt: observations and confidence

1. **Search only runs on explicit submit.** `android-app/lib/main.dart` `browse()` sets `query` and calls `reload()` only on keyboard submit or search icon press; typing does not update results. The older results are replaced by a full-page spinner while the request is pending. Both can feel like search is broken or slow. The Worker receives at most 100 chars and uses substring matching on title or creator; app default is `updated_desc`, not relevance, so exact matches may be buried. These are source findings, not proof of the specific cause of the user's delay.
2. **The delay isn't measured.** `CatalogApi.list` has a 15-second timeout and starts a network request for every explicit search with no latency instrumentation; the user reports a massive delay, but device/network/Worker response latency hasn't been measured. A fetched public Worker search for `Trollcraft` returned one matching item and creator (no timing recorded). It does not establish app-device speed or every query. Worker tests passed including literal search, relevance and pagination; bot sync tests passed. No Flutter SDK/emulator is present locally. Build and phone behavior are not tested in this planning step.
3. **Request completion is manual.** `BotDownload` only permits one active UUID until `finish()` is invoked. Simply deleting the button without replacing the state transition will prevent subsequent downloads. The current matcher accepts bot document messages later than the request, not a provable request identifier. The checked-in bot backup may emit a thumbnail, multiple documents/photos/videos and a promotion and has no request marker on each media message. The owner reports the live bot returns the right files, and the screenshot shows Trollcraft saved. The deployed bot is reported revision 68, different from the checked-in backup, and has not been inspected in this step.
4. **Catalog/UI gaps visible in source/screenshots.** Current cards lack Download/Share; the detail screen omits file extension and clickable creator/category; settings is one uncategorized list, and search field is rectangular. Current share history stores name/title/category/URI but not item UUID/version. The app uses an older green seed (`0xff426854`) and standard M3 widgets, not the requested expressive motion system. Screenshot confirms the current screen appearance, not motion quality or all text scaling behavior.
5. **Storage choice is not implemented.** On Android 10+, `MainActivity.kt` saves through app-owned MediaStore to a known Downloads category, not a freely configurable absolute path. Android 9 and earlier uses a per-file save picker. A file icon currently has no folder picker.
6. **Profile gaps.** The pinned TDLib schema (`1.8.69`, SHA `4c6377aa7386`) supports `getMe`, `getUserFullInfo`, `first_profile_audio`, `getUserProfileAudios` and numeric ID. Registration `accountInfo` applies to another user who initiated a chat and may be unknown; no verified self-registration-date getter was found. Do not conflate current session login date with Telegram account creation.

## Plan, matching the user's points

### 1. Search correctness and latency
- Reproduce with exact terms and timing on the user's Android device: input to debounce, request start, first bytes, parsing, frame render and image load, without logging the actual query, phone/session data or uploading diagnostics. Include first/cold vs repeated search, network loss, rapid typing and slow/out-of-order responses.
- Add an interruptible 250–350 ms debounce while typing, immediate search on keyboard action/icon, and cancel/invalidate stale requests with a generation token so old responses cannot overwrite new ones. Clearing restores browsing; reset page on query/filter changes, keep filter selection visible and protect latest response across navigation.
- Keep previous results visible with a small loading indicator, then show useful result count, empty/retry/offline state. Choose relevance for active text queries by default while respecting explicit sorting; server currently searches the whole catalog by title or creator, case-insensitive SQLite LIKE (not typo tolerance). Test exact, partial, special characters, creator, pagination, all filters and multiple results.
- Avoid caching in conflict with the existing Worker's `no-store` policy. Use request deduplication/connection reuse and only ephemeral UI state while request is pending; any persistent cache or Worker/index change needs separate policy/deployment review. Measure again; no guarantee of a particular speed without device testing.

### 2. Material 3 Expressive, rounded, squishy motion
- Establish independent Material 3 Expressive styling: rounded filled/tonal controls, cards and sheets with polished typography and clear hierarchy. Flat colors only, no gradients, glows, AI button/symbols, decorative emoji or arrows. Keep one phone card per row and responsive larger layouts.
- Add short spring-driven press/release scale and shape morph on key buttons, chips, navigation indicators, expanding panels and cards, plus coordinated sheet/page transitions. Motion is interruptible, no layout jump or excessive bounce, no autoplay; use stable hit targets and natural animation timings. Use Flutter-supported components and independent implementation, not GPL PixelPlayer source/assets.
- Respect Android remove-animations / reduce-motion settings with static or minimal fades; test talkback semantics, 48dp targets, contrast and large text.

### 3. Theme color `#874F9E`
- Replace the green accent seed with exactly `#874F9E` as the default Alium brand color; derive appropriate light/dark Material schemes and ensure legible contrast. Seed color is exact; generated surface/foreground tones may differ by design. Update icon treatment only if needed so the flower identity stays consistent.

### 4. Categorized Settings
- Group cleanly into **General** (account, navigation/help as appropriate), **Appearance** (theme mode and accent), **Downloads** (location and behavior), and **About & Support** (brand/channel/support). Use compact rounded grouped cards, section headers, descriptive accessible labels, no repetitive explanatory blocks. Keep sign-out in account.

### 5. Remove specified text
- Remove the exact download-request and unaffiliated-catalog sentences from the screens, and the long account introduction specified in point 14. Do not replace them with another persistent wall of tips. Retain necessary clear consent once at sign-in/first user-initiated bot request and useful failures only; the user must know the request acts through their account. Keep factual affiliation/legal information available in About if needed, not on every detail page.

### 6. Hide Open in Telegram while signed in
- Hide the normal detail-screen Telegram button when TDLib is authorized. Signed-out users get sign-in and/or explicit Telegram action. If a bot join gate, not-started state, timeout or failure occurs, show a contextual **Open Telegram** recovery action even when signed in, because it is the only way to resolve some gates; never auto-open or auto-join. Preserve native `tg://` first and optional web fallback.

### 7. Remove Finish request and warning copy
- Remove the Finish button and both quoted warning paragraphs, including duplicate status text, from detail and Downloads; replace with a clear, automatic state machine so a completed, canceled, timed-out or failed operation releases its slot and the next download can begin. Preserve real progress, retry and cancellation. Multiple bot-sent files and end-of-response handling require explicit tests; don't finish early after only the first document.
- The owner says their bot sends the correct file. The checked-in backup and this client do not prove which request a document belongs to, particularly with delayed replies or another Telegram session. The cleanest safe one-tap design is a backward-compatible opt-in request identifier echoed by the live bot for each response and an explicit end/error marker, with app-side validation, deduplication and bounded timeout. This needs the actual live rev68 source, isolated testing and **separate approval before any bot deployment**; don't touch the 12 schema changes. Without proven correlation, retain an unobtrusive file-choice control in ambiguous cases (no quoted warning paragraphs) rather than silently saving a potentially unrelated file. Do not claim verified one-tap until proven.

### 8. Website-like detail screen and links
- Show responsive rounded cover, title and labeled rows: Name, Studio, Category, File type, File size, Version when known, Marketplace price only when real. Reuse current public Worker detail endpoint by UUID; extend `CatalogItem` for `file_ext` and other real response fields. Tapping studio filters catalog using Worker's exact `creator`; tapping known category opens that category, preserving Back/scroll state. Empty/invalid fields show Not available, and invalid URLs never become arbitrary links.
- Prominent Download and Share actions; inline progress and errors. Preserve existing catalog data and avoid inventing ratings, dates or price. ToolCoin metadata remains separately unverified; do not bundle its other features.

### 9. Download on catalog cards
- Add a clearly labeled/accessible Download control per card, plus Share from point 10, without opening an unnecessary request-file page. Use the same download controller and intent/consent behavior as detail, update inline with state and offer Downloads navigation; card tap still opens details and controls do not accidentally trigger card tap. Handle unsigned-in, already active, canceled, gate and retry states.

### 10. Share in catalog and download/detail
- Use Android native share sheet and Copy link with the **same website canonical HTTPS item URL** as `catalog-v13.js`. Port and test exact NFKD normalization, diacritic removal, lowercase, 64-char title limit and hyphen trimming, version normalization/truncation/duplicate suppression, lowercase UUID, and the current site origin. Golden cross-language test vectors cover punctuation, accents, empty title/version and repeated version. Send title and URL; never send Telegram file IDs/session data.
- Put Share on catalog cards, details and downloaded items. Extend download history with item UUID/title/version and migrate old entries safely: if an old record lacks UUID, try only an unambiguous catalog lookup or show link unavailable rather than guessing from filename. If user meant sharing the downloaded file instead, present it as a separate explicit action with a granted content URI; do not silently replace link sharing. Image attachments/previews depend on recipient/network support.

### 11. Alium deep links
- Add in-app routing for examples `alium://browse`, `alium://downloads`, `alium://settings`, `alium://item/<uuid>` and search/filter routes. Treat these as proposed syntax until finalized; accept both cold-start and already-running intents, validate exact scheme/host/path/UUID/allowlisted parameters, reject oversized/malformed values and unknown routes, and **never** trigger a download or authentication automatically from a link. Custom schemes aren't verified and can conflict with other apps.
- To make the *same website shares* open Alium directly when installed, additionally support verified HTTPS Android App Links for the existing website item URLs, `/home` and compatible routes. Requires a domain-controlled `/.well-known/assetlinks.json` with package ID and correct signing-certificate fingerprint, reachable without redirect/challenge, plus app intent filters; test debug/release signatures. InfinityFree currently has a security challenge that may block verification; do not bypass it or claim success. Ask for separate website deployment approval, preserve `.htaccess` and private `config.php`; until verification succeeds HTTPS links open the website or system chooser as configured.

### 12. More Appearance themes
- Keep persisted System / Light / Dark separately from a persisted **accent palette**. Default Alium `#874F9E`; offer a few solid accessible accents, e.g. botanical green, slate blue and warm amber. Optional system dynamic color only where supported, with deterministic fallback. No gradients/glow/neon; label selected state, preview colors, validate contrast in both modes, restore choice on restart. Theme palettes are proposed, not supplied by the user; the user may choose alternatives.

### 13. Change download location
- Default visible label `/storage/emulated/0/Download/Alium`, with categories under it on normal primary-storage Android 10+ devices. It is a human-readable indication of the default, not a promise that all volumes/providers expose a real raw path. Keep actual storage as MediaStore content URIs and allow the category folder scheme.
- Make the folder icon and row open Android's directory picker for a user-selected location; persist the granted tree URI, create category subfolders through DocumentsContract, handle canceled/revoked permission, moved files, full disk, unsupported providers and restore default. Existing downloads stay where they were. Android 11+ restricts choosing the Downloads **root**, other roots and protected directories; offer an allowed subfolder or another location rather than bypassing Android. On old Android, retain system-picker-compatible fallback. Never request all-files access. Test real Android 9/10/11/current across internal/SD/providers.

### 14. Telegram profile, bio, ID, joined date and music
- Replace the long paragraph after sign-in with a professional profile: avatar, display name, username, numeric Telegram ID (copy on tap), bio and an AyuGram-inspired compact profile-music card matching the provided example. Fetch only the user's own data via `getMe`/`getUserFullInfo`, subscribe to changes, and use pinned TDLib 1.8.69 `first_profile_audio` / `getUserProfileAudios`. If music exists, show metadata/thumbnail and user-initiated play/pause via a maintained Android audio player; handle codec/loading/error and audio focus; no autoplay. If no track, show a small empty state or omit it. No unrelated AyuGram privacy/ghost features or credentials.
- `accountInfo.registration_month/year` in this pinned schema applies to certain *other* users and can be unknown; a reliable way to obtain this user's own join date has not been established. Investigate permitted official APIs on the real account, display month/year only if Telegram actually supplies it, otherwise `Not available`. Never guess from user ID or label session login as join date. Keep sign-out and privacy controls; profile stays local.

### 15. Search bar, icon and filter UI/UX
- Replace the tall outlined rectangle with a rounded filled Material SearchBar-style field; place Search and Filters on its **right, in that order**, with 48dp targets, clear button, semantic labels, visible focus, keyboard search action, active-filter count and easy reset. A rounded expressive filter sheet groups category/date/sort and keeps applied state. Accommodate 320dp widths, large text, keyboard, RTL and screen readers. Search behavior is covered in point 1.

## Test and release gates

- Flutter unit/widget tests: search debounce/out-of-order/timeout/clearing/pagination/filter state; current versus pending results; deep link routing and injection; exact share URL parity against website fixtures; old/new history migration; profile nullable fields; settings persistence; available catalog metadata; 320–1440dp + large text + reduced motion and semantics.
- Fake TDLib tests: bot requests in rapid succession, delayed/duplicate/unrelated messages, multiple media items, save errors, join gate, timeouts, automatic state cleanup, content URI permissions. No assertion of exact match unless verified protocol exists.
- Android instrumentation/real phone: install update without losing session/history; measure network/render latency before/after; verify actual folder choice and saved content; Telegram signed-in/out and gate fallback; app links, custom links cold/warm, sharing targets, theme and audio focus. Compare screenshots/animation, run Flutter analyze/tests and debug APK CI. A passing build or mocked test is not proof of real-device behavior.
- No Worker, bot or website deployment is authorized by `/plan`; seek separate approval for those deployments. No private credentials in chat. Preserve InfinityFree protections, Worker binding/CORS, bot compatibility and the $0 constraint.
