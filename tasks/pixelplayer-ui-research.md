# PixelPlayerOSS and website UX research

Date: 2026-11-27. Scope: research and planning only; no website code changed in this milestone.

## Method and limits

User specified [PixelPlayerHQ/PixelPlayerOSS](https://github.com/PixelPlayerHQ/PixelPlayerOSS). A temporary shallow clone at commit `1664e8e636b57655a4f47dc9f3325b081cb02fc9` was inventoried across all tracked files: 1,605 tracked files, of which 1,569 were UTF-8 text (approximately 411,379 lines), including 942 Kotlin and 560 XML files. Automated filename and keyword searches covered the repository. Focused source reading covered theme, theme preferences, setup, segmented controls, tab animation, artwork caching, native image sharing, navigation and component references. This was **not a semantic, line-by-line review of all 411,379 lines**, a full security audit, or an Android build/run. The exact clone is outside the repository and is not a website dependency.

The repository is GPL-3.0; do not copy its source or assets into this website without reviewing license obligations and attribution. Prefer independently implemented web patterns inspired by concepts, not copying code or appearance. PixelPlayer is a native Jetpack Compose app, not a website; Android gestures, system color extraction, app-intent sharing and its disk cache cannot simply be imported into PHP/JS.

## Concrete source findings

1. **Three modes and theme tokens:** [Theme.kt lines 162–225](https://github.com/PixelPlayerHQ/PixelPlayerOSS/blob/1664e8e636b57655a4f47dc9f3325b081cb02fc9/app/src/main/java/com/lostf1sh/pixelplayeross/ui/theme/Theme.kt#L162-L225) selects dark/light, supports OS dynamic colors and configures `MotionScheme.expressive()`. [ThemePreferencesRepository.kt lines 20–30](https://github.com/PixelPlayerHQ/PixelPlayerOSS/blob/1664e8e636b57655a4f47dc9f3325b081cb02fc9/app/src/main/java/com/lostf1sh/pixelplayeross/data/preferences/ThemePreferencesRepository.kt#L20-L30) defaults to following system. Website adaptation: a labeled Auto / Light / Dark preference, use CSS semantic tokens and `prefers-color-scheme` in Auto, robust persistence, no promise of Android wallpaper-derived colors on the web. Preserve this user's no-gradient/no-glow/no-AI-color preference.
2. **Radii, controls and state:** [Shape.kt](https://github.com/PixelPlayerHQ/PixelPlayerOSS/blob/1664e8e636b57655a4f47dc9f3325b081cb02fc9/app/src/main/java/com/lostf1sh/pixelplayeross/ui/theme/Shape.kt) defines small/medium/large rounded shapes; [ToggleSegmentButton.kt lines 195–235](https://github.com/PixelPlayerHQ/PixelPlayerOSS/blob/1664e8e636b57655a4f47dc9f3325b081cb02fc9/app/src/main/java/com/lostf1sh/pixelplayeross/presentation/components/ToggleSegmentButton.kt#L195-L235) animates background and shape while exposing on/off semantics. Website adaptation: a small set of semantic shape and color tokens and visible selection with accessible pressed/checked state; do not add decorative controls or stars.
3. **Animation is not only springs:** [TabAnimation.kt lines 40–90](https://github.com/PixelPlayerHQ/PixelPlayerOSS/blob/1664e8e636b57655a4f47dc9f3325b081cb02fc9/app/src/main/java/com/lostf1sh/pixelplayeross/presentation/screens/TabAnimation.kt#L40-L90) uses both tweened colors and an interaction-triggered scale/translation, skips initial selection animation. The shared toggle uses a spring for radius and a 250 ms color tween. Website adaptation: short interruptible state transitions, controlled shape/scale on button press, share sheet enter/exit; no motion needed for content or navigation. Honor `prefers-reduced-motion` by removing nonessential transitions, and test for layout shift and no endless loading animations. Values are design choices to evaluate, not an assertion of official web tokens.
4. **Native share is not web share:** [RecapShare.kt lines 19–48](https://github.com/PixelPlayerHQ/PixelPlayerOSS/blob/1664e8e636b57655a4f47dc9f3325b081cb02fc9/app/src/main/java/com/lostf1sh/pixelplayeross/presentation/recap/RecapShare.kt#L19-L48) renders a local PNG and hands a URI plus text to Android's chooser with read permissions. A web page instead requires a readable `File`, `navigator.canShare({files})`, a secure context and user activation. Browsers/targets vary and a website cannot preselect an arbitrary native target through Web Share. Do not promise attachment for all devices.
5. **Cache only useful validated data:** [RemoteArtworkCache.kt lines 23–35 and 75–102](https://github.com/PixelPlayerHQ/PixelPlayerOSS/blob/1664e8e636b57655a4f47dc9f3325b081cb02fc9/app/src/main/java/com/lostf1sh/pixelplayeross/data/image/RemoteArtworkCache.kt#L23-L102) checks image signatures and avoids caching error bodies; it deduplicates concurrent image downloads and handles cancellation. Website adaptation: validate cached catalog response shapes, cache only successful public data, bound size and age, deduplicate requests, never cache 404/429/error bodies as successes, show age or stale/offline status and maintain retry. The Android cache is not a direct web implementation.
6. **Not adopted:** app-specific music-player sheets, audio widgets, artwork-derived colors, blur/glow, overly decorative morphing, AI features, unrelated sign-in, and music controls. User requested a Bedrock catalog, no AI styling, and flat solid colors.

## Current live-site observations

- `/home`, the InsaneCraft readable slug, and legacy `addon.php?uuid=...` independently loaded on InfinityFree after upload. The home showed 27 entries and real Download and Share controls. The host appended `?i=1` during the browser check. These are fetch-based observations, not a complete live device test.
- Screenshot shows the site in a 3-column, desktop-like layout on a phone. It is consistent with a wider effective CSS viewport (e.g., Chrome's Desktop site mode), but the screenshot alone does not prove the cause. Local checks covered one column below 600 CSS px. First ask the user to check Chrome menu → Desktop site is off, and verify viewport/zoom and phone rendering before changing breakpoints.
- The site currently hardcodes dark theme (`color-scheme:dark` and many literal dark/light colors), has native Share or copy fallback, and on every new document initializes catalog fetch. The explicit back link goes to `/index.php#catalog` rather than history, so it is a fresh navigation; browser Back may instead restore the previous document from bfcache. Worker public responses currently specify `Cache-Control: no-store`; do not quietly change its privacy/freshness contract without a deliberate, tested decision.
- The user's three Telegram URLs resolved to public Telegram pages during research. Keep the download bot link (`@Mc_addonbot`) for file delivery separate from the main channel and support links. Opening or receiving every item is not confirmed.

## Sharing reality and asset requirements

- Custom sheet: visually consistent, labeled Telegram, WhatsApp, Discord, More, and Copy link. Telegram documents a [URL/text sharing link](https://core.telegram.org/widgets/share); that does not itself attach an image. WhatsApp link-sharing can pass text/URL; an attachment is not automatically included by a normal share URL. A Discord-specific web share endpoint/attachment flow is **not verified**; use native share chooser or copy-link fallback rather than claim an unverified integration. Apps must not be named as direct destinations if the sheet cannot actually choose them.
- More uses the OS share sheet on a fresh user gesture. If thumbnail bytes can legally and technically be read, validate image type/size, prepare a `File` ahead of the final tap, then use `navigator.canShare({files})` and `navigator.share` with URL/text where supported. If fetching fails, CORS blocks bytes, target strips text/file, permission is denied or feature absent, explicitly offer link-only sharing and copy link. Never state an image is attached unless it actually is. [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/share) and [W3C](https://w3c.github.io/web-share/) document capability and transient-activation constraints. `img` display does not prove cross-origin image bytes are readable; [MDN CORS-enabled images](https://developer.mozilla.org/en-US/docs/Web/HTML/How_to/CORS_enabled_image). Our exact image hosts' CORS support has not yet been measured in the user's browser. Do not build an open arbitrary-URL proxy; a narrowly allowlisted, size-limited audited proxy would need separate design, security and budget review.
- Use official platform brand assets only where their terms permit; scalable official SVG is sharper than a large 4K raster at mobile icon sizes. [Discord brand guidelines](https://discord.com/branding), [WhatsApp official guidance](https://faq.whatsapp.com/5913398998672934); verify actual Telegram mark usage terms for a share button before bundling. Google [Material Symbols](https://developers.google.com/fonts/docs/material_symbols) are Apache 2.0; include only needed symbols locally with required license notice. The user clarified not to create 100 separate icons—replace unwanted decorative symbols with functional, professionally labeled icons where useful.
- The InfinityFree challenge and client-side item metadata can prevent messaging app crawlers from reading dynamic previews; an attached file through a supported share sheet is distinct from a link preview. No rich preview or automatic image guarantee.

## Caching, theme and privacy research

- Determine actual back/forward-cache eligibility with DevTools and `pageshow.persisted`; distinguish browser Back from the site's explicit Back to collection link. Restore filters, pagination and scroll without blindly re-fetching when restored. [web.dev bfcache](https://web.dev/articles/bfcache) notes public `no-cache` can support bfcache while `no-store` can reduce eligibility. PHP currently uses HTML `no-cache`; Worker metadata `no-store` is a separate response.
- If permitted by revised public metadata policy, introduce bounded session-only cache keyed by normalized query/category/page, schema version and API origin; validate response shape, avoid secrets, cap size/entries, and define fresh/stale expiration and offline/deletion behavior. Render fresh session data instantly, revalidate based on chosen TTL, expose stale indication, honor removal and retry. Handle quota/private mode/corrupted entries/time changes and clear state on deployment/schema change. Never silently treat a Worker `no-store` response as permission for durable storage; decide and document headers/API policy before storage. Compare request counts before/after; caching does not fix incomplete sync or deletion reconciliation.
- Theme: use CSS variables for **all** colors (including status, input, footer, focus, errors and disabled); Auto follows system changes; store only preference when possible and handle denied storage. Set early in document to minimize flash; serve sensible no-JS default; reflect `color-scheme` and theme-color; test both modes for 4.5:1 normal-text contrast and focus/forced-colors without claiming compliance. [MDN prefers-color-scheme](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-color-scheme).
